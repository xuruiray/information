Development & Programming Briefing

This edition of Development & Programming tracks the rapid evolution of AI-assisted coding and cloud-native developer tooling. Languages & Frameworks Briefing

This subsection focuses on platform and tooling updates from Vercel: Hermes Agent gains Vercel AI Gateway and Sandbox support, skill packs enable sharing agent skills, every Herdr agent can run in an isolated Sandbox, and audit logs now stream to Datadog, Splunk, and Panther. No core language releases were reported, but these workflow upgrades shape modern development and security operations.

Hermes Agent Now Supports Vercel AI Gateway and Vercel Sandbox Vercel 博客

Hermes Agent can now use Vercel AI Gateway as its inference layer and run agent commands in an isolated Vercel Sandbox microVM. Users gain access to 200+ models at no token markup, with every request appearing in the AI Gateway dashboard alongside usage and spend.

Read more → Audit Log Drains Now Support Datadog, Splunk, and Panther Vercel 博客

Vercel's Audit Log Drains now stream team activity events to Datadog, Splunk, and Panther, in addition to existing custom HTTPS endpoints and Amazon S3 destinations. Available to Enterprise plans, this helps teams centralize security auditing and operational monitoring. Every event includes additional audit metadata for deeper investigation.

Read more → Skill Packs Now Available on skills.sh Vercel 博客

Skills.sh now lets developers bundle multiple agent skills into shareable packs, drawing from community skills, local folders and zips, or public and private GitHub repositories. Each pack gets an unlisted URL, allowing teams to standardize project skills with a simple one-command install. Packs can be shared with one person or an entire team.

Read more → Herdr Agents Can Now Each Run in Their Own Vercel Sandbox Vercel 博客

Herdr, a tmux-style manager, now lets terminal coding agents such as Claude Code, Codex, and OpenCode run in their own isolated Vercel Sandbox, orchestrated side by side in panes. Nothing agents run or edit touches the host machine; project files are uploaded into a fresh sandbox when a session starts.

Infrastructure & Data Briefing

In infrastructure and data, Datasette 1.0a38 fixes a SQL injection issue affecting instances that serve both public and private tables with granular permissions. Administrators are urged to disable execute-sql where needed; a backport is available in the 0.65.3 branch. The fix highlights the importance of input validation in data publishing tools and follows a security-first release process.

Datasette 1.0a38 Fixes SQL Injection Security Issue Simon Willison

Datasette 1.0a38 fixes a SQL injection security flaw affecting instances that serve a mix of public and private tables in the same database with access configured via the Datasette permission system. Administrators with private tables are advised to disable the execute-sql permission on affected instances. A backport to the 0.65.3 branch is also available.
