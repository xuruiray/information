Vercel infrastructure updates: caching, Daemons, and geolocation

Vercel merged Data Cache into Runtime Cache, unifying data caching across frameworks and APIs; Next.js fetch caching and unstable_cache require no code changes, while Pro and Enterprise projects get larger storage. Daemons can call services within their deployment through service bindings, with Vercel handling internal routing, authentication, and TLS, and can configure HTTP liveness checks. IP geolocation now provides city-level data for nearly all requests and postal-code data for 90% of traffic, enabled by default without code or configuration changes.

Vercel has merged Data Cache into Runtime Cache, giving developers one caching product across frameworks and APIs. Next.js fetch caching and unstable_cache need no code changes, while Pro and Enterprise projects receive larger storage allocations.

Vercel Daemons can now call services within their deployment through service bindings. Developers declare the target service and an environment variable for its URL, while Vercel handles internal routing, authentication, and TLS.

Read more → Add liveness checks to your Daemons Vercel 博客

Vercel Daemons now support configurable HTTP liveness checks. Developers expose a lightweight health endpoint, point a livenessProbe value at it, and Vercel periodically requests it to determine whether the daemon remains healthy.

Read more → IP geolocation now covers more visitors at higher resolution Vercel 博客

Vercel's IP geolocation now resolves visitor locations with finer network granularity, providing city-level data for nearly all requests and postal-code data for 90% of traffic. Data refreshes more often and is enabled by default.
